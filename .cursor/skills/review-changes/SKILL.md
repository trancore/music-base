# 変更をレビューする

リポジトリ固有の設計と規約を根拠に差分をレビューする。レビュー中はファイル、ステージ状態、コミットを変更しない。

## 1. リポジトリを理解する

差分を評価する前に、次を確認する。

- リポジトリルートの `AGENTS.md` と `.cursor/rules/project-agents.mdc`
- `git status --short --branch`、現在のブランチ、デフォルトまたは PR のベースブランチ
- README、アーキテクチャ文書、主要なマニフェスト、解析・テスト設定
- ソース、テスト、ドキュメントのディレクトリ構成と、変更箇所に隣接する実装
- 変更に関係する外部 API やパッケージの仕様（公式資料を優先）

## 2. レビュー単位を確認する

差分を読む前に、ユーザーへ必ず次のどちらでレビューするか確認する。依頼文で指定されていても確認する。

- **commit 単位**: ステージ済み差分だけを対象にする。
- **PR 単位**: ベースブランチから現在の `HEAD` までのコミット済み差分だけを対象にする。

レビュー単位を推測して進めない。

### commit 単位

- `git diff --cached --stat`、`git diff --cached` で対象を確定する。
- ステージ済み差分が空なら停止する。ユーザー自身によるステージを求め、代わりにステージしない。
- 未ステージ変更と未追跡ファイルを対象へ混ぜない。

### PR 単位

- ベースブランチを特定し、`git diff <merge-base>..HEAD` を対象にする。
- ステージ済み、未ステージ、未追跡の変更を対象へ加えない。
- 使用したベース参照と merge-base をレビュー結果へ記載する。

## 3. 差分を検証する

パッチだけで判断せず、呼び出し元、インターフェース、関連テスト、関連ドキュメントを読む。

変更によって新しく生じた、または悪化した問題だけを指摘する。根拠のない推測、好みだけのスタイル指摘、変更範囲外の既存問題は含めない。

変更内容に応じた非破壊の検証を実行する。フォーマッターはチェックモードを使い、ファイルを書き換えない。

観点: アーキテクチャ、正確性、セキュリティ、プラットフォーム差異、性能、テスト、ドキュメント。

## 4. 指摘を報告する

重大度:

- **P0**: データ損失、秘密情報漏えい、広範な停止
- **P1**: 通常利用経路を壊す、リリースを妨げる高確率の問題
- **P2**: 特定条件で誤動作、回復不能、重大な性能劣化
- **P3**: 影響は限定的だが修正価値がある明確な問題

各指摘:

```text
- [P1] 短いタイトル — path/to/file:line
  問題: 何が誤っているか
  影響: どの条件で何が起きるか
  根拠: 差分と周辺実装から確認した事実
  修正案: 最小限の修正方針
```

指摘がなければ `指摘なし` と明記する。

## 5. コミット前に停止する

コミット依頼の一部として実行している場合、P0〜P3 で 1 件でも指摘があれば `git commit` を実行しない。ユーザーが続行を明示するまでコミットしない。
