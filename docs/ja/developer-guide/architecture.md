# アーキテクチャ

アプリは、UI、状態管理、ドメインロジック、データアクセス、プラットフォーム固有処理を分離します。初期実装ではRiverpodを状態管理と依存注入に、go_routerを画面遷移に使用します。

## ディレクトリ構成

- `lib/app/`: アプリ起動、Provider構成、テーマ、ルーティング
- `lib/domain/`: アプリ設定などのモデルと抽象インターフェース
- `lib/data/`: SharedPreferencesによる設定保存、ローカルディレクトリスキャン、音楽再生、DriftによるライブラリDB
- `lib/presentation/`: 画面とUIコンポーネント
- `lib/platform/`: Windowsなどプラットフォーム固有処理の境界

ローカルファイルアクセス、SMBアクセス、音楽再生、MusicBrainz連携、タグ処理、CDリッピング、音声解析は独立したサービス境界として追加します。外部サービスのレスポンスやプラットフォームAPIを、そのままUIへ渡してはいけません。

## 永続化

設定はSharedPreferencesへ保存します。ライブラリ情報のキャッシュはDrift SQLiteデータベースへ保存し、現在は音源パス、曲名、アーティスト、アルバム、最終確認日時を保持できる土台を用意しています。音源ファイル本体は保存せず、選択されたローカルディレクトリまたはSMB共有を正本として扱います。

ローカルディレクトリスキャナーはサブディレクトリを再帰的に走査し、FLACとMP3をライブラリ候補として扱います。ファイル形式やタグの追加対応はスキャナーとメタデータサービスの境界内で行います。

音楽再生は`PlaybackService`の抽象インターフェースを通じて利用します。現在の実装はjust_audioとWindows実装を使用し、ファイルパスを音源として再生します。UIは再生エンジンへ直接依存せず、サービスの状態を表示します。

プレイリストは`PlaylistRepository`の抽象インターフェースを通じて保存します。現在はSharedPreferencesへプレイリスト名と音源パスを保存し、再生時に現在のライブラリキャッシュから音源モデルを解決します。音源ファイル本体はプレイリストへコピーしません。

MusicBrainz連携は`MusicBrainzService`を通じて利用します。APIクライアントはJSONレスポンスを`MusicBrainzRelease`へ変換し、識別可能なUser-Agent、1秒あたり1リクエスト以下の間隔制御、検索結果のメモリキャッシュを適用します。

SMB接続は`SmbService`の抽象インターフェースを通じて利用します。接続情報のうちホスト、共有名、サブフォルダ、ユーザー名は設定へ保存し、パスワードは`flutter_secure_storage`へ保存します。SMBスキャナーは接続テストとは別のサービス処理として共有内を再帰走査し、FLAC/MP3をライブラリDBへキャッシュします。SMB再生は`StreamAudioSource`のレンジ要求をSMBの部分読み込みへ変換し、音源本体をアプリへコピーせずに再生します。

参照先の切断、認証失敗、ファイル消失などは復旧可能なエラーとして扱い、UIやサービス全体をクラッシュさせない設計にします。

CD検出とリッピングはWindows固有機能です。AndroidではローカルディレクトリまたはSMB共有の参照と再生を提供し、Windows固有のCD処理を共有ドメインコードへ直接混在させません。

CD取り込みの出力計画は`CdImportPlanner`で作成します。MusicBrainzの曲順とCDトラック数を検証し、FLAC／MP3の拡張子、タグ候補、出力パスを組み立てます。既存パスの上書きは計画段階で拒否し、実ドライブの読み取りとエンコードはWindows固有のサービスから呼び出します。

WindowsのCDドライブ検出は`CdDriveService`の境界で扱います。Windows実装はPowerShellから`Win32_CDROMDrive`のドライブ文字、デバイス名、メディア挿入状態を取得します。Androidや非Windows環境では利用可能性をエラーとして返します。

CDトラック一覧は`CdTrackService`で扱い、Windows実装はCD AudioのMCI APIからトラック数と長さを取得します。MCI呼び出しとPowerShell実行はWindowsデータ層に閉じ込め、共有層は`CdTrack`モデルだけを受け取ります。

音声データの取り込みは`CdRippingService`で扱います。Windows実装は外部`ffmpeg.exe`へCDドライブ、トラック番号、FLAC／MP3 codecを渡し、`-n`と事前存在確認で上書きを防止します。`CdRippingCancellationToken`により実行中のプロセスを停止できます。ffmpeg未導入や実行失敗は通常の復旧可能なエラーとして扱います。
