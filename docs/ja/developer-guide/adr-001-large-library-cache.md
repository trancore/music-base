# ADR 001: 大規模ライブラリのキャッシュ

## 決定

最大10万曲のライブラリを扱うため、SQLiteを一覧・検索・再生順の正規キャッシュとします。一覧は200件のキーベースページング、検索はFTS5の単語前方一致、画像はSHA-256で重複排除して表示時に読み込みます。

再スキャンはパス、更新日時、サイズが変わった音源だけメタデータを再解析します。走査結果は全件の取得に成功してから1トランザクションで反映します。ローカル走査と同期メタデータ解析は専用isolateで実行します。UIは再スキャン中も開始前のページを保持し、完了後に再取得します。失敗時も表示中のキャッシュを維持します。SMB障害時は直近のローカル参照先へ一時的にフォールバックします。

## 理由

全曲と全画像のメモリ展開、全件ソート、全行Widget生成は曲数に比例して起動時間とメモリ使用量を増加させます。DBに検索・順序・画像管理を委ねることで、画面と再生サービスが必要な範囲だけ取得できます。
