# PRを作成する

## 概要

現在のブランチを安全にpushし、リポジトリのデフォルトブランチを対象とするドラフトPRを作成する。ローカルの対象範囲を守り、PRテンプレートがあれば使用し、マージやレビュー準備完了の判断はユーザーに委ねる。

## 手順

### 1. 前提条件を確認する

- 作業前に、適用される `AGENTS.md` と `.github/pull_request_template.md` を読む。
- `git status --short --branch` と差分を確認し、ベースブランチ、リモート、リポジトリ名を特定する。
- 無関係な変更や対象が曖昧な変更を含む作業ツリーを、確認なしに公開しない。
- `gh --version` と `gh auth status` を確認する。認証がない・期限切れの場合は `gh auth login -h github.com` を案内する。APIスコープ不足が表示された場合は、エラーに示されたスコープを使って `gh auth refresh -h github.com -s <scope>` を実行し、ブラウザまたはデバイス認証の完了を待つ。

### 2. ブランチを準備する

- `main`、`master`、またはリモートのデフォルトブランチ上にいる場合は、`agent/<short-description>` 形式の作業ブランチを作成する。
- コミットが存在し、作業ツリーに意図しない変更がないことを確認する。
- push前に関連する検証を実行する。実行できない検証は、成功したように扱わず理由を記載する。
- ユーザーがレビュー準備完了を明示しない限り、ドラフトPRを作成する。

### 3. pushする

- `git push -u origin <branch>` でtracking付きpushを行う。
- PR作成前に、pushしたブランチとベースブランチの差分を確認する。
- force push、ブランチ削除、マージ、無関係なリモート状態の変更は行わない。

### 4. PR本文を作成する

- 完全な差分を要約する簡潔なタイトルを付ける。
- PRタイトルは日本語で付ける。技術名・ブランチ名・識別子など、必要な固有名詞は原表記のまま残してよい。
- `.github/pull_request_template.md` がある場合は、そのセクション順を守る。対象範囲、検証、ドキュメント、セキュリティ、既知の制約を実際の状態で埋める。
- 変更内容、変更理由、利用者・開発者への影響、バグ修正時の原因、実行した検証コマンドを記載する。
- `docs/` など特定のパスを意図的に除外した場合は明記する。

### 5. 作成して確認する

- ブランチのpush後は、原則として `gh pr create --draft` を使用する。既存PRの更新には `gh pr edit <number>` を使用し、重複PRを作らない。
- ベースブランチが明らかでない場合は明示する。`gh repo view --json nameWithOwner,defaultBranchRef` でリポジトリ情報を確認する。
- 作成されたPRのURL、番号、タイトル、base/headブランチ、ドラフト状態、本文を確認し、残っているローカル変更も報告する。
- ユーザーが明示的に依頼しない限り、レビュー準備完了への変更、マージ、クローズ、レビューコメントの解決は行わない。
