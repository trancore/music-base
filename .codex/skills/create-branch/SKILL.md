# 作業ブランチを作成する

push、PR作成、既存コミットの変更を行わず、依頼された作業用のローカルGitブランチを作成する。

## 手順

1. 参照を変更する前にリポジトリを確認する。

   - 適用される `AGENTS.md` を読む。
   - `git status --short --branch` と `git remote -v` を実行する。
   - 利用できる場合は `git symbolic-ref refs/remotes/origin/HEAD` でデフォルトブランチを特定する。利用できない場合は、リポジトリ設定またはローカル・リモートブランチから `main` / `master` を判断する。
   - ブランチの起点が不明確な場合は、現在のブランチと直近のコミットを確認する。

2. 既存の作業を保護する。

   - `git reset`、`git clean`、`git checkout --`、強制操作、破壊的なコマンドを使用しない。
   - 未コミットの変更はユーザーの所有物として扱う。現在のブランチが依頼に適した作業ブランチなら、そのまま使用し、新しいブランチを作らなかったことを報告する。
   - 現在のブランチがデフォルトブランチで、作業ツリーに変更がある場合は、現在の `HEAD` から新しいブランチを作成する。Gitにより作業ツリーの変更は新しいブランチにも保持されるため、そのことを明示する。
   - 依頼内容が既存ブランチと衝突する場合、または切り替えにより無関係な作業が危険にさらされる場合だけ、確認を求めて停止する。

3. 簡潔なブランチ名を決める。

   - このリポジトリおよびCodexが作成するブランチでは、`agent/<短い説明>` を優先する。
   - 小文字、数字、ハイフンを使用し、句読点や秘密情報を含めない。
   - 依頼された変更を表す名前にする。例: `agent/add-bilingual-docs`、`agent/fix-library-scan`。
   - 既存の名前を上書きしない。依頼されたブランチであることが明らかな場合だけ確認して切り替え、それ以外は `-v2` のような一意な接尾辞を付ける。

4. ブランチを作成して確認する。

   - 新規ブランチには `git switch -c <branch-name>` を使用する。
   - 作成後に `git status --short --branch` と `git log -1 --oneline --decorate` を実行する。
   - ブランチが意図した開始コミットを指し、既存の変更が保持されていることを確認する。

## 引き継ぎ

ブランチ名、開始コミット、作業ツリーがクリーンだったか、保持した未コミット変更を報告する。ユーザーが別途依頼し、関連するワークフローを使用する場合を除き、pushやPR作成は行わない。
